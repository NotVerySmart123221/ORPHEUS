## Findings

- **Beta-targeted build:** launcher checks the selected executable against MD5 `fe3ad8a77eef77b383df4929aed816fd` (`repo/Prometheus-Launcher/main.cpp:157,293-320`) and launches it suspended before injecting `PrometheusCore.dll` (`:17-33,46-97,216-224`). `game_main/.build.info:2` and `game/.build.info:2` both identify `0.8.0.0.24919`; the former is an alternate staging with a patched executable, not retail. No 1.74 dev build/research was found in project filenames or searched Markdown/text/JSON/YAML. Only 1.74 hit was the torrent filename `overwatch.-multi.-1.74.0.0.104319-dev-hackers.-7z_archive.torrent`; it was not opened.
- **Build target and achieved build:** root CMake assembles Atlas, Generation, Core, Launcher and Patcher (`repo/CMakeLists.txt:34-59`); Core and Launcher use C++23 (`repo/Prometheus-Core/CMakeLists.txt:1-10`, `repo/Prometheus-Launcher/CMakeLists.txt:1-10`). Existing work reports successful fresh MSVC Core/Launcher builds and successful scoped practice/combat, respawn, map/hero transition and normal-exit checks (`research/PROJECT_MAP.md:65`; `research/baseline-2026-10-30/REPORT.md:10-15,42-59`). These are beta build results, not a retail compatibility result.
- **Hook/core architecture:** DLL initialization sets `gameBase` to the main module and then uses fixed RVAs, decryption callbacks and byte checks (`repo/Prometheus-Core/dllmain.cpp:899-963`; main-loop RVA `repo/Prometheus-Core/Fixes/MainLoop.cpp:9-41`). `StartHook` rejects one loaded-thread mode, but the inspected section does not show a retail version/signature dispatch before beta-specific setup. The launcher hash gate and hard-coded hook/layout assumptions make this code unsafe to carry over unchanged to 1.74. A fresh retail address/layout survey and per-hook validation would be prerequisite work.
- **Local game versus server:** documented workflow is launcher → injected Core → hooks and game-thread updates → local resource/statescript replacements. The project map explicitly says state-replication scaffolding does not establish a working multiplayer server (`research/PROJECT_MAP.md:42`). This is an offline local restoration, not a demonstrated server or networked service.
- **Bot scope:** beta client lacks the server AI brain/navigation and server-only statescript node implementations; the fork adds ordinary simulated hero bots, a custom `BotBrain`, and selective AI runtime handlers (`repo/CHANGES.md:108-135,506-600,687-701`). The implementation leaves unknown AI task/node types skipped (`repo/CHANGES.md:532-600`). These are concrete systems and techniques to mine, but their structs, resource IDs, message IDs, node IDs and native hooks are build-specific.
- **Prior outcomes:** the baseline reached six-bot practice and checked damage, death/respawn, map/hero transitions and normal exit (`research/baseline-2026-10-30/REPORT.md:42-59`). A later report documents full 21-hero coverage plus focused successful Reaper aura, Zarya barrier, Lúcio shield, Mercy heal, Graviton and D.Va weapon checks; it separately lists unfinished Reinhardt Shockwave/Firestrike delivery and remaining gameplay limitations (`research/hero-sweep-2026-10-30/REPORT.md:3,10-13,47-51`). Treat these as validated beta behaviors and reusable scenario ideas, not proof for another executable.

## Reuse candidates

- **Strongest reuse: concepts and test harness.** Local practice-mode state progression, bot lifecycle, health/damage/death handling, projectile cleanup, and repeatable automation scenarios can guide a new implementation. The successful beta scenarios and known failure boundaries are documented in `research/hero-sweep-2026-10-30/REPORT.md:19-30,38-51` and implemented in `repo/Prometheus-Core/Fixes/` (source list includes `Bots`, `BotBrain`, `Damage`, `ModifyHealth`, `ServerNodes`, `PracticeMode`, and AI modules at `repo/Prometheus-Core/CMakeLists.txt:198-238`).
- **Potentially reusable tooling:** command/screenshot orchestration and local asset/state inspection are documented at `research/PROJECT_MAP.md:38-40`; `tools/owctl.py`, `tools/owlaunch.py`, and CASC/IDA helpers can supply workflow patterns after their executable paths, process assumptions and resource formats are checked. Reuse is an inference; these tools are not shown working against retail.
- **Not reusable as-is:** injected DLL initialization, RVA hooks, recovered layouts/offsets, beta-only hashes/resources and the current launcher’s version gate. They are bound to 0.8.0.0.24919 (`repo/Prometheus-Launcher/main.cpp:157,293-320`; `repo/Prometheus-Core/dllmain.cpp:910-963`; `repo/Prometheus-Core/Fixes/MainLoop.cpp:10,38-41`).
