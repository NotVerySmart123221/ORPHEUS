# Weapon UX assets and missing main HUD

## Findings

The weapon graph’s UXPresenter states 68–70 reference three local assets: `0x0A8800000000023F`, `0x0A88000000000240`, and `0x0A880000000002AB`. Their parameters bind loadout `0x0B9000000000008D`, weapon/entity/instance values, logical buttons, and for state 70 instance values 53 and 198. The catalog does not name these assets or parameters as ammo, health, or crosshair widgets. The successful weapon UX state frame therefore establishes that these presenters can be active; it does not establish that they are the main HUD. The current frame’s no-HUD result is consistent with the separate HUD path described below.

Build-104319 CASC lookup verified asset `0x0A8800000000023F` as an 80-byte STU payload with CKey/MD5 `F58C8CBF744EA75EC80C3996FE5650E2`, stored at offset `0xBCC15` in bundle `0x0D9088411C29B98D`. Its root field `0xB91CFF97` decodes to parent asset `0x0A8800000000023E`. Asset `023E` is 357 bytes, CKey/MD5 `2A0F2E91970BA8314DEA7C1FD96FE0B0`, at offset `0xBCAB0` in the same bundle. It contains seven instances, but its class `0x35DC2BEA` and nested classes `0x49552462`/`0x4AE65C7C` have no matching semantic definitions in local OWLib [KnownTypes.csv](<beta-project>/names/KnownTypes.csv); its embedded IDs (`0x0D80000000000201`, `0x0D8000000000631B`, `0x0D800000000061EF`) remain opaque. Thus parent links and payload integrity are verified, but UI meaning is not.

Sibling `0x0A88000000000240` is 208 bytes (CKey/MD5 `25E9064DEF190A65F290D1565155DF63`) and points to `0x0A88000000000234`; `0234` points to `0x0A880000000002BF`. Sibling `0x0A880000000002AB` is 260 bytes (CKey/MD5 `1A009DF47E45DBA2F3EF777C6BECBBE3`) and points back to `023E`. These records form a resource-reference chain, not a decoded widget hierarchy. Do not label these resources as specific HUD elements without a matching schema or visible runtime evidence.

The concrete main-HUD candidate is Practice controller child graph `0x20E4`. Its owner state 25 (node 34, `STU_9D7BF987`) consumes entity-scoped dynamic variables `17906` and `18405`, with remote-sync IDs `0x0D800000000045F2` and `0x0D800000000047E5`. Current controller frame code sends only entity variables `2438` and `31435`; it does not send `17906` or `18405`. A prior owner-state-only test showed no HUD, but did not supply these variables. Their meanings and whether either should reference the player entity or possessed body remain unresolved. The graph’s client-only UXPresenter nodes reference assets `0x0A880000000002BE`, `0x0A88000000000236`, and `0x0A88000000000251`; available catalog data does not name their widgets either.

## Evidence and limits

- Local CASC lookup validates each payload’s CKey against MD5 before reporting it; parser checks are in [retail_bundle_lookup.py](../tools/assets/retail_bundle_lookup.py#L119) and output formatting in [lines 150–166](../tools/assets/retail_bundle_lookup.py#L150). The STU asset-reference decoding is in [lines 60–68](../tools/assets/retail_bundle_lookup.py#L60).
- The three weapon UXPresenter asset IDs and parameter bindings are from the pinned 1.74 graph catalog and are summarized in [hud-restoration.md](hud-restoration.md#L81). The Practice HUD owner-state variables, scopes, and current frame omissions are documented at [lines 3–15](hud-restoration.md#L3); the frame assembly is in [heroselect.py](../tools/lobby/vendor/ow174/game/heroselect.py#L70).
- **Direct evidence:** resource GUIDs, payload sizes, hashes, bundle offsets, parent references, graph nodes/variables, and code’s current serialized variables.
- **Inference:** missing entity variables `17906`/`18405` are a plausible reason the Practice main HUD remains absent. No tested assignment or successful HUD render establishes that causal link.
- **Unknown:** semantic names for assets `023E`, `023F`, `0240`, `02AB`, and the `20E4` client-only UI assets; intended values of `17906`/`18405`; whether additional client-only setup is required.
