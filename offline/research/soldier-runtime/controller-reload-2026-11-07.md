# Controller reload and empty-magazine input

User reported that manual reload could fail even while standing still, and primary fire could continue at zero displayed ammo. The launch command was the normal `python tools/lobby/run.py <game-root> --asi tools/asi/build/retail_menu.asi`; the user confirmed a controller. Guarded keyboard tests reproduced ordinary reload/refill, so those tests alone did not establish controller behavior.

The Soldier initializer omitted the authored reload LogicalButton3 (logical input14), while registering primary LogicalButton8 (logical input20) permanently. The weapon sender also left primary input enabled during reload and at empty ammo. The saved correction registers reload3 and explicitly disables primary8 while `ammo == 0` or the update is reloading. The final accepted shot still carries Volley10 and muzzle feedback; its subsequent explicit Stop remains present. Removing Volley10 is not equivalent to stopping it and was rejected in a diagnostic control.

Native format: both input states use class `B480A974`. Helper classifier `217FEB5..217FEC7` returns true. Delta reader `1C2C807..1C2C844` consumes the explicit control bit; false calls End through `1C2C87F`, clearing active bit1 at `2D9068D`. LogicalButton DSR `2DBC380` consumes four counter bits. Input callback `2DBC726` and held-input reconciliation `2DBD286` require the active bit before dispatch. A present state with payload `0 0000` therefore disables both input paths; outer presence0 merely skips its update.

Regression tests fail on the previous initializer/input gate and pass after the correction. The Match/command test covers manual reload, a refused trigger during reload, refill/re-enable, the final accepted round, and refusal at empty ammo. The historical body-probe byte comparison excludes the later reload-input registration alongside its existing later-feature exclusions; the historical probe is unchanged. Full suite: **352 passed in 11.63s**; `git diff --check` passes.
